# 通用排轴常识

具体敌人、地形与活动机制查 PRTS；Copilot 字段查 MAA 协议。本卡用于规划，不代替实战证据。

## 部署顺序与承伤

- 常规远程索敌通常优先攻击范围内最后部署的干员；嘲讽、隐匿与特殊索敌会改变优先级。
- 安排输出、治疗和承伤者的部署顺序；补下脆皮或撤退再部署后，重新核对仇恨与治疗覆盖。

## 部署位与再部署

- 编队人数不等于场上部署上限；上限以关卡情报和 HUD 为准。召唤物是否占位按机制核对。
- 满部署位时需明确安排 `Retreat`；系统预设关卡不能按自有编队处理。
- 常规再部署费用逐次增加，第二次约为原费用的 1.5 倍，第三次起约 2 倍；取整、返费与特例按机制确认。
- 撤退返费不代表下次部署免费。换防前同时核对费用、部署位、再部署冷却和潜能影响。

## 技力与首放时间

- 游戏表的 `initSp`（查询结果技能 `max` 中的 `sp_init`）是落地已有的**初始技力点**，不是秒数；`sp_cost` 是释放所需技力点，`duration` 才是持续秒数。
- 仅在自然回复、回复速度已知且无额外技力效果或锁技力阶段时，理论首放等待可估为 `max(0, sp_cost - sp_init) / 回复速度（点/秒）`。
- 攻击回复、受击回复及特殊技力机制不能直接套用该式；额外充能、天赋和技能状态也可能改变结果。
- 理论末级技能数据不代表账号实际技能等级或专精。实际值未知时，首放估算只能作为带假设的方案，不能当作确定时间轴。

## 动作条件与结果

- 优先使用实际可达的 `kills`、费用等可观测条件，再在确需对齐时附短延迟；输出变化会改变击杀触发时刻，仍需复核。
- 无敌人死亡的机制窗口不能只等 `kills`，否则动作可能一直等待。
- 排轴前核对地图坐标、站位类型与射程。Copilot 链完成后仍需原生胜负证据，不能由动作执行完毕推断通关。
