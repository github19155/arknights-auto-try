# 执行注意事项

面向本项目 MAA 接口与任务 overlay 的通用约束。协议细节及版本差异通过 `lookup_knowledge` 查询官方文档。

## 模板路径与链入口

- 模板名应相对资源模板根目录，例如 `Battle/StartButton/StartButton1.png`。出现 `templ not found` 时先核对相对路径和 MAA 资源版本。
- 不把链首节点的 `exceededNext` 当作通用失败调度器；入口可使用 `JustReturn` 锚点，将识别候选放入 `next`，并按所用 MAA 协议确认分支语义。

## OCR 匹配范围

- 面板标题可能包含装饰性前后缀，标题确认与地图标签识别应分别设置匹配策略。
- 关卡标签需要避免短代号误命中长代号；例如子串匹配可能把 `1-1` 命中为 `1-10`。精确标签使用 `fullMatch`，不要把标题区策略直接复用于地图标签。

## 战斗结果与退出

- Copilot 链完成不等于胜利。执行器追加 `ResultFailedCheck` / `ResultWinCheck`，只有明确胜利证据才判为通关。
- 停止 Copilot 不等于放弃成功；暂停菜单、选中干员遮罩或生命点暂时消失也不证明已退出。
- 未确认退出时保留事件与最后截图，不在活战斗上尝试面板归位，也不自动重跑。`ABANDON_FAILED`、`EXIT_UNCONFIRMED` 和未知结果需重新观察并人工决策。

## 截图与坐标

- 截图按实际格式解码：PNG 编码字节不能当作裸 RGB 缓冲。当前解码器也支持尺寸匹配的裸 RGB 与 PIL 图像，不应无条件翻转 RGB/BGR 通道。
- 截图与点击工具使用 1280×720 基准。反投影地块、拖拽方向和 UI 区域必须结合画面复核，不能把推算坐标当作已验证动作。
- 画面识别与交互优先复用 MAA 原生接口及资源，识别失败应暴露证据，不用猜测结果替代识别。
